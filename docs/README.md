# Docs Guide

Start here for shipped behavior and current implementation boundaries.

## Canonical references

- `docs/CORE_ARCHITECTURE.md` describes the shipped application architecture.
- `docs/DATA_MODEL.md` defines the current data contracts.
- `docs/planner-api-implementation-boundaries.md` defines the planner/editor API seam and Airtable adapter boundary.
- `docs/backend-drill-api.md`, `docs/backend-session-api.md`, and `docs/backend-import-api.md` describe the current backend route behavior.

## Archive

`docs/archive/` holds historical material, not active implementation guidance.

## Layout

- `docs/*.md` - authoritative architecture, data model, UX, quality and API docs.
- `docs/guides/` - how-to guides (user guide, search, testing, mobile, performance).
- `docs/security/` - checklist, action items, review and incident reports.
- `docs/archive/` - historical material (completed tasks 009-028, legacy research, old feature notes). Not guidance.
- Plans live in `/plans`; work is tracked in GitHub Issues.
